# 18_CUSTOMER_PORTAL_SPEC.md

# PROJECT C

Customer Portal

Версия: 1.0.0

Статус: Functional Specification

---

# 1. Назначение

Customer Portal является личным кабинетом клиента.

---

Назначение:

* управление лицензиями;
* управление доменами;
* управление подписками;
* просмотр платежей;
* скачивание PRO;
* продление лицензий.

---

# 2. Основная цель

Клиент должен самостоятельно выполнять все операции без обращения в поддержку.

---

# 3. Авторизация

Поддерживается:

```text
Email + Password
```

---

В будущем:

```text
Google Login
GitHub Login
Telegram Login
```

---

```text
Dashboard
```

# 6. Блок лицензий

```text

Домен
```

---

Пример:

```text

ACTIVE

site.ru

01.06.2027
```

```text

```

---

# 12. Продление лицензии

Доступно из карточки лицензии.

---

Пользователь выбирает:

```text
1 месяц

6 месяцев

12 месяцев
```

---

После оплаты:

срок продлевается автоматически.

---

# 13. Смена домена

Для лицензии:

```text
1 лицензия = 1 домен
```

---

Действие:

```text
Освободить домен
```

---

После подтверждения:

домен удаляется.

---

Лицензия остается активной.

---

# 14. Ограничение смены домена

Версия 1.0:

```text
не более 5 смен в месяц
```


---

# 32. Производительность

Все страницы должны открываться:

```text
до 2 секунд
```

---

при обычной нагрузке.

---

# 33. Ограничения

Пользователь не может:

```text
создавать лицензии

менять статус лицензии

удалять платежи

редактировать историю
```

---

# 34. Подготовка к масштабированию

В будущем кабинет должен поддерживать:

```text
несколько продуктов

несколько лицензий

партнерскую программу

реферальную систему
```

---

# 35. Связь с API

Все данные получаются только через:

```text
REST API
```

---

Прямой доступ к БД запрещен.

---

# 36. Definition of Done

Customer Portal считается завершенным если клиент способен самостоятельно:

* зарегистрироваться;
* войти в систему;
* купить лицензию;
* продлить лицензию;
* привязать домен;
* скачать PRO;
* посмотреть историю оплат;
* управлять своим аккаунтом.

---

# 37. Главная цель

Клиент должен иметь возможность полностью управлять своими лицензиями и подписками без участия администратора и без обращения в поддержку.
