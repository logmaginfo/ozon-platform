# 11_FREE_DATABASE_SCHEMA.md

# PROJECT A

WordPress Plugin FREE

Версия: 1.0.0

Статус: Database Specification

---

# 1. Назначение документа

Документ описывает:

* структуру хранения данных;
* wp_options;
* post_meta;
* кэш Ozon;
* хранение логов;
* правила совместимости.

---

# 2. Основной принцип

Используем только штатные механизмы WordPress.

Приоритет:

1. wp_options
2. post_meta
3. Action Scheduler (в PRO)
4. Собственные таблицы (только если невозможно иначе)

---

Для FREE собственные таблицы запрещены.

---

# 3. Пространство имен

Все данные Ozon обязаны использовать префикс:

```text
ozon_
```

или

```text
_ozon_
```

---

# 4. wp_options

Используются следующие записи.

---

## ozon_client_id

Тип:

string

Назначение:

Client ID Seller API

---

Пример:

```text
123456
```

---

## ozon_api_key

Тип:

string

Назначение:

API Key

---

Пример:

```text
abcdef123456
```

---

## ozon_categories

Тип:

json

Назначение:

полный индекс типов товаров

---

Пример:

```json
{
  "22801": "Навигатор < Автомобильные навигаторы < Электроника",
  "22802": "Проектор < Проекторы < Электроника"
}
```

---

## ozon_categories_version

Тип:

string

Назначение:

версия кэша категорий

---

Пример:

```text
2026-06-10
```

---

## ozon_last_categories_sync

Тип:

datetime

Назначение:

дата обновления категорий

---

Пример:

```text
2026-06-10 12:35:20
```

---

## ozon_plugin_version

Тип:

string

Назначение:

текущая версия FREE

---

Пример:

```text
1.0.0
```

---

# 6. Кэш характеристик

Для уменьшения нагрузки используется локальный кэш.

---

Option:

```text
ozon_attributes_cache
```

---

Структура:

```json
{
  "22801": {
    "updated_at": "2026-06-10 21:00:00",
    "attributes": []
  }
}
```

---

# 7. Кэш справочников Ozon

Option:

```text
ozon_dictionary_cache
```

---

Структура:

```json
{
  "85": {
    "updated_at": "2026-06-10 21:00:00",
    "values": []
  }
}
```

---

# 8. История товара

FREE не хранит полную историю.

Хранится только последнее состояние.

---

История появится в PRO.

---

# 9. Логи FREE

Используется стандартный WooCommerce Logger.

---

Источник:

```php
wc_get_logger()
```

---

Источник данных:

```text
WooCommerce → Status → Logs
```

---

# 10. Формат логов

Каждая запись должна содержать:

* дату;
* действие;
* результат;
* описание.

---

Пример:

```json
{
  "action":"export_product",
  "product_id":125,
  "result":"success",
  "task_id":"45872136"
}
```

---

# 11. Подготовка к PRO

Структура FREE обязана быть совместима с PRO.

---

PRO использует те же метаполя.

---

Запрещено менять имена:

```text
_ozon_status

_ozon_task_id

_ozon_last_upload

_ozon_last_check

_ozon_error

_ozon_type_id

_ozon_type_name

_ozon_attributes
```

---

# 12. Подготовка к PORTAL

FREE не хранит лицензии.

---

FREE не хранит платежи.

---

FREE не хранит домены.

---

Данные лицензирования появятся только в PRO.

---

# 13. Резервное копирование

Все данные FREE должны корректно переноситься через:

* экспорт WordPress;
* резервную копию БД;
* миграцию сайта.

---

# 14. Обновления плагина

Обновление FREE не должно:

* удалять настройки;
* удалять категории;
* удалять атрибуты;
* удалять метаполя товаров.

---

# 15. Миграции

Для FREE миграции БД запрещены.

---

Допускается только:

создание отсутствующих wp_options.

---

# 16. Definition of Success

Схема данных считается завершенной если:

* все настройки сохраняются;
* все данные товара сохраняются;
* категории кэшируются;
* атрибуты кэшируются;
* статусы сохраняются;
* структура совместима с будущими версиями PRO и PORTAL.

---

# 17. Главный принцип

Любой товар после выгрузки должен полностью восстанавливаться из базы данных WordPress без обращения к HTML-формам и без повторного ввода данных пользователем.
