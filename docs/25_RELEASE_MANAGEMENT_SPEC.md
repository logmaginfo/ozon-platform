# 25_RELEASE_MANAGEMENT_SPEC.md

# OZON PLATFORM v1.1

Release Management Specification

Версия: 1.0.0

Статус: Product Release Policy

---

# 1. Назначение

Документ определяет:

* правила выпуска релизов;
* жизненный цикл версий;
* поддержку версий;
* обновления клиентов;
* исправление ошибок.

---

# 2. Область применения

Документ распространяется на:

```text
PROJECT A
FREE Plugin
```

```text
PROJECT B
PRO Plugin
```

```text
PROJECT C
License Platform
```

---

# 3. Главный принцип

Каждая версия должна иметь:

```text
Номер версии

Статус

Дата выпуска

Историю изменений

Период поддержки
```

---

# 4. Типы релизов

Поддерживаются:

```text
Alpha

Beta

Release Candidate

Stable

Hotfix
```

---

# 5. Alpha

Назначение:

внутренняя разработка.

---

Разрешается:

```text
Нестабильный код

Ломающие изменения

Неполный функционал
```

---

Использование клиентами запрещено.

---

# 6. Beta

Назначение:

тестирование функционала.

---

Разрешается:

```text
Ограниченный круг пользователей
```

---

Допускаются ошибки.

---

# 7. Release Candidate (RC)

Назначение:

финальная проверка перед релизом.

---

Требования:

```text
Все функции завершены

Критических ошибок нет
```

---

# 8. Stable

Продакшен версия.

---

Требования:

```text
Пройдены тесты

Пройдены проверки безопасности

Обновлена документация
```

---

# 9. Hotfix

Используется для:

```text
Критических ошибок

Проблем безопасности

Ошибок оплаты

Ошибок лицензирования
```

---

# 10. Семантическое версионирование

Формат:

```text
MAJOR.MINOR.PATCH
```

---

Пример:

```text
1.0.0

1.1.0

1.1.1
```

---

# 11. MAJOR

Используется если:

```text
Ломается обратная совместимость
```

---

Примеры:

```text
Изменение API

Изменение структуры лицензий

Изменение базы данных
```

---

# 12. MINOR

Используется если:

```text
Добавляется новый функционал
```

---

Примеры:

```text
Массовая выгрузка

Новые отчеты

Новые интеграции
```

---

# 13. PATCH

Используется если:

```text
Исправляются ошибки
```

---

Без изменения логики.

---

# 14. Релизный цикл

Стандартный цикл:

```text
Feature
↓
Develop
↓
Beta
↓
RC
↓
Stable
```

---

# 15. Минимальные требования к релизу

Перед выпуском:

```text
Все тесты проходят

Нет критических ошибок

Обновлен changelog

Обновлена документация
```

---

# 16. Release Checklist

Обязательно проверить:

```text
API

Платежи

Лицензии

Обновления

Авторизацию

Очереди
```

---

Каждый релиз обязан содержать:

```text
Added

Changed

Fixed

Removed
```

# 21. Поддерживаемые версии

Поддерживаются:

```text
Текущая Stable

Предыдущая Stable
```

---

# 22. End Of Support

Версия снимается с поддержки если:

```text
Выпущено две более новые Stable версии
```

---

# 23. Security Fix Policy

Проблемы безопасности исправляются:

```text
Независимо от релизного цикла
```

---

Через Hotfix.

---

# 24. Критические ошибки

Критическими считаются:

```text
Невозможность выгрузки товаров

Невозможность оплаты

Невозможность активации лицензии

Потеря данных
```

---


---

High:

```text

```

---

Medium:

```text
7 дней
```

---

Low:


Обновляются через:


---

# 27. Обновления PRO

```text
License Server
```

---

После проверки лицензии.

---

# 28. Проверка лицензии перед обновлением

Проверяется:

```text
License Active

License Not Expired

Domain Match
```

---

# 29. Обновление с истекшей лицензией

Разрешается:

```text
Использовать текущую версию
```

---

Запрещается:

```text
Получать новые версии
```

---

# 30. Обратная совместимость

Каждый MINOR релиз обязан:

```text
Поддерживать предыдущие настройки
```

---

# 31. Миграции БД

При обновлении:

```text
Автоматические миграции
```

---

Обязательны backup перед запуском.

---

# 32. Release Notes

Каждый релиз публикует:

```text
Что нового

Что исправлено

Что удалено

Известные проблемы
```

---

# 33. Релизы PRO

Публикуются только после:

```text
Успешного прохождения CI/CD
```

---

# 34. Релизы Platform

Требуют:

```text
Проверки Billing

Проверки License API

Проверки Customer Portal
```

---

# 35. Аварийный откат

При критической ошибке:

```text
Rollback Previous Stable
```

---

Должен выполняться менее чем за 30 минут.

---

Удаление запрещено.

# 43. OpenHands Policy

OpenHands может:

```text
Создавать PR

Готовить релизы

Обновлять документацию
```

---

OpenHands не может:

```text
Публиковать Stable Release
```

---

Без подтверждения владельца.

---

# 44. Definition of Done

Release Management считается завершенным если:

* существует единый релизный цикл;
* существует политика версий;
* существует политика поддержки;
* существуют процедуры обновления;
* существует процедура отката;
* существуют правила исправления ошибок.

---

# 45. Главная цель

Любая версия OZON PLATFORM должна иметь предсказуемый жизненный цикл, понятные правила поддержки, безопасное обновление клиентов и возможность быстрого отката в случае возникновения критических проблем.
